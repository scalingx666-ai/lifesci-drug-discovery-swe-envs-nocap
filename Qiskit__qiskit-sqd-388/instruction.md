# Issue

**Title:** Unify the carryover with StandardPolicy

## Description

This is the literal unification requested in review of #383: `TrimPolicy.carryover_ratio` becomes `carryover_threshold`, the same amplitude cutoff `StandardPolicy` uses, with the same `1e-4` default. It is offered as a PR so the diff can be judged directly rather than described.

The change is small because `_select_carryover` already composes a threshold with a count ceiling in two stages, so no plumbing was needed. The screening trims keep `trim_ratio`; only the carryover selection changes.

Two things to weigh:

- `TrimPolicy` ends up with two different *kinds* of knob — a fraction for screening, an absolute cutoff for the carryover. The `carryover_threshold` docstring got longer, not shorter, because that distinction now needs explaining.
- `max_carryover` defaults to `None`, so a default `TrimPolicy()` has an unbounded carryover count. We can consider a dimension-dependent default as a follow-up, which is where that belongs.
