# Issue

**Title:** Docs: getting started, Python API and CLI reference, built in CI

## Description

A documentation site for Ersilia, built from the source code on every change and published to GitHub Pages.

## What's in it
- **Getting started:**
  - Install Ersilia.
  - Find a model in the [catalog](https://catalog.ersilia.io) or with `ersilia catalog --hub`.
  - Fetch, serve, run and close `eos4e40`, from the command line and from Python, with a comment on each step.
- **Python API:** reference for `Model` and `Catalog` (#1931), with what the API guarantees:
  - the same options, defaults and checks as the CLI
  - quiet unless `verbose=True`
  - never prompts or ends the process
  - errors raised as `ErsiliaError` subclasses
- **Command-line interface:** every command and option, generated by `sphinx-click`, so it always matches `ersilia <command> --help`.
- **Package reference:** every module, generated by `sphinx-apidoc`.

The site uses the Furo theme. The index links to the model catalog and the Ersilia Book.

## How it is built
- A new workflow, `.github/workflows/docs.yml`:
  - **Pull requests** that touch `ersilia/` or `docs/`: it builds the site, so a broken docstring fails the check.
  - **Pushes to `master`:** it builds the site and publishes it to the `gh-pages` branch.
  - It runs `sphinx-apidoc` and then `sphinx-build`, after `pip install -e ".[docs]"`.
- `pyproject.toml`: the `docs` extras add `sphinx-click`.
- `docs/conf.py`:
  - enables `sphinx_click`
  - skips duplicate API entries
  - mocks `bioservices`, `nox` and `streamlit`, optional imports that would otherwise make autodoc skip the modules that use them
  - drops two theme options that Furo ignores
