# Issue

**Title:** Add guide for using the SBD eigensolver

## Description

Adds a guide for using the [SBD eigensolver](https://github.com/Qiskit/sbd-eigensolver-python) as an alternative SCI solver, alongside the existing Fulqrum and Dice guides.

### The guide

`docs/guides/integrate_sbd.ipynb` follows `integrate_dice_solver.ipynb` closely: the same N2 / 6-31g / 16-orbital workload, the same uniform random samples, and the same three-cell shape. Since `sbd.sbd_solver.solve_sci_batch` already matches the `sci_solver` interface, the guide binds its options with `functools.partial` and passes it straight through — no wrapper function, which makes this guide shorter than the Fulqrum one. Running on a GPU is mentioned in prose rather than code, since CI has no GPU.

With `fcidump_path` left unset, SBD regenerates an FCIDUMP from `hcore`/`eri` with `ECORE=0`, so `result.energy` is the pure electronic energy and the guide adds `nuclear_repulsion_energy` exactly as the other two guides do. No data files are added to the repo.

### Packaging

New `sbd` optional dependency, mirroring the existing `fulqrum` one:

```
pip install qiskit-addon-sqd[sbd]
```

It is also pulled into `notebook-dependencies`, so — unlike the Dice guide — this one is exercised by `tox -e notebook` in CI.

### CI

`sbd-eigensolver` publishes no wheels; it compiles a C++ extension against the local MPI and BLAS. `setup.py` finds both automatically once they are present (`mpicc` on `PATH`, OpenBLAS on the system path), so no `MPI_HOME` / `BLAS_LIB_PATH` variables are needed. The three test workflows and `docs.yml` now install OpenMPI and OpenBLAS — via apt on Linux, and via the existing `brew install` step on macOS. `test_development_versions.yml` additionally builds `sbd-eigensolver` from a git clone and pins the resulting wheel, matching how fulqrum is handled there.

### Also

Corrects a stale `how_tos/` URL in the fulqrum release note — that guide lives under `guides/`, so the link was dead.

### Verification

`tox -e lint` passes and all `overview.rst` references resolve. The notebook itself could not be run locally: `tox -e notebook` and `tox -e docs` both stop at the `sbd-eigensolver` build with `Could not detect MPI. Please set MPI_HOME environment variable, or ensure mpicc is on PATH.` — reproducible in a clean venv, and purely the absence of a local MPI toolchain rather than anything about this change. CI is therefore the first place the notebook actually executes; I am watching the runs.

The macOS job is the least-proven path here. SBD's `setup.py` has a Darwin branch that builds against Homebrew `libomp`/`openblas`, but SBD's own CI is Linux-only, and the pre-existing macOS step points `CC`/`CXX` at Homebrew LLVM clang while SBD's README recommends system clang so that libc++ matches Python's.
