# Issue

**Title:** Write text, HTML, RTF and pictures to the clipboard in one native call

## Description

## Summary

A new Tauri command, `write_clipboard_items`, clears the clipboard once and writes every flavour of a copy together on macOS and Windows: private ChemDraft data, plain text, HTML, RTF, PNG and PDF. It is the shared writer for two pieces of work: copying structures into Word and PowerPoint as pictures that keep their data, and copying tables as HTML/RTF that Word and Excel read.

**What this PR does not change:** plain Copy (⌘C / Ctrl+C) still writes only ChemDraft's private data (plus plain text when the selection contains text). Pasting into Word or PowerPoint after a plain Copy still gives them nothing to show. Making plain Copy also put a picture on the clipboard is the follow-up structure-copy work, which builds on this writer. Copy As ▸ PNG/SVG already goes through the new writer.

- Every item is validated **before** the clipboard is cleared, so a bad call never wipes what the user had copied.
- Items are required by default; optional ones (pictures) may fail without failing the write. The result names what was written, which requested items failed, and warnings for platform extras that were skipped.
- Duplicate types are validated too; the first of each type is kept, and it is required if any duplicate was (same rule in TypeScript and Rust).
- **Windows:** HTML goes under the registered `HTML Format` with a correct CF_HTML header (pure, tested builder) and is refused before clearing if it lacks the `<!--StartFragment-->`/`<!--EndFragment-->` markers; RTF under `Rich Text Format` (ASCII only). Nothing is written under a format literally named `text/html`. PNG writes `PNG` and `image/png` whenever the PNG is valid, plus `CF_DIBV5` when the picture is small enough (its IHDR size is checked before decoding). Reading HTML strips the CF_HTML header.
- **macOS:** `text/html` → `public.html` (no markers needed), `text/rtf` → `public.rtf`, `image/png` → `public.png`, `application/pdf` → `com.adobe.pdf`.
- **Browser fallback** (web build): byte-backed `text/plain` items are decoded as strict UTF-8; invalid bytes fail the write instead of being garbled.
- Binary data crosses IPC as base64, not JSON number arrays.
- `writeClipboardTextItems` and `writeClipboardImage` keep their signatures and delegate to the new call; the old native commands remain thin wrappers.

## Known limitations

- Plain Copy is unchanged (see Summary). No caller writes HTML/RTF through the new command yet; the structure-copy and table work build on it.
- `CF_DIBV5` is an uncompressed bitmap, so a large high-resolution picture makes a heavy one: 40.5 MB for one β-cyclodextrin copied at 4× oversampling. That is inside the size check but slows the copy and bloats the Windows clipboard. The structure-copy work will write the DIB at a lower resolution (or under a pixel cap) while keeping the PNG at full resolution.
- RTF must be 7-bit ASCII; callers escape non-ASCII themselves.
