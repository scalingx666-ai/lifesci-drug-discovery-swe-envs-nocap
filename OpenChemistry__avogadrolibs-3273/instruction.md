# Issue

**Title:** Fix PluginManager::pluginFactory() returning the wrong plugin

## Description

When no factory had the requested identifier, pluginFactory<T>() fell off the end of the loop and returned the last factory it had looked at (or an uninitialized pointer when there were no plugins at all), so a lookup of an unknown id silently handed back an unrelated plugin.

Return nullptr when nothing matches. Add a regression test
